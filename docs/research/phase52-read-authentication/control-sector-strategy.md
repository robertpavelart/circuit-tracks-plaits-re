# Phase52 — what control sectors establish

**PROVEN:** mode1 maps USB LBA40hex→D4000. In the reference normal-layout model, target64 is VBR, controlA65 is first FAT and controlB73 is fixed-root start. These are distinct physical sectors in the same internal disk, all read-only metadata. For another valid layout, derive controls from candidateBPB: USB LBA64+fatbase, then64+dirbase. Do not hardcode65/73 for the current unit. No current-unit sector contents or full512-byte inequality are known. [physical-binding.md](<../phase50-msd-readonly-geometry/physical-binding.md>); [native_sequence.py](<../../../builds/phase52-read-authentication/native_sequence.py>) `SECTORS`.

**STRONG INFERENCE safest candidate:** the first FAT sector is preferable to arbitrary file/data sectors because its location is derived, it is metadata, and reserved FAT entries give some structural checks. This is conditional on a bounded candidateBPB and proven binding; it is not authenticated by location alone. Root metadata is a possible second control but may be mostly/all zero. A second FAT copy may be identical to the first and is not independent control entropy.

**PROVEN baseline:** native T1→C1→T2 satisfies full4096-byte equality T1=T2 and inequality T1!=C1, as well as the same512-byte comparisons and BPB validation. **PROVEN counterexample:** no-byte false completion atC1 returns zeroes; T1=T2!=zero still passes the requested basic rule. Adding a control-FAT header check rejects that zero-control case, but a partial FAT prefix can reproduce the full normal zero-tailed FAT sector and pass even full4096-byte comparisons. authentication-experiment.json (local-only reference: `builds/phase52-read-authentication/authentication-experiment.json`; not distributed) `baseline`, `independent_faults`.

**PROVEN two-control limit:** T→A(partial8)→T→B(partial27)→T passes equality of all targets, full-sector target/control inequalities and A!=B. The modeled FAT's last nonzero byte is7; root directory's last nonzero byte is26. After clearing, those short prefixes are byte-identical to their full sectors. This is not incorrect target geometry; it disproves using the sequence to certify that every control read fully refreshed its buffer. authentication-experiment.json (local-only reference: `builds/phase52-read-authentication/authentication-experiment.json`; not distributed) `five_read_partial_controls` includes all five native traces.

**PROVEN:** interleaving does disturb the buffer at successful control-return, but that disturbance is erased before the next target DMA. It cannot act as a host-selected nonzero fill pattern for the next target. More controls cannot replace the missing native completion/provenance contract merely by adding comparisons. **UNKNOWN:** a finite normal-read sequence that closes the actual fault model rather than the restricted prefix model. No smallest fully authenticating sequence has been qualified.
