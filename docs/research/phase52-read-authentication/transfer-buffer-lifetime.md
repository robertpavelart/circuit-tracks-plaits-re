# Phase52 — READ10 buffer lifetime

**PROVEN:** normal LUN0 READ10 uses fixed buffer40024000..40024FFF (4096 bytes). SCSI3B508 loads40024000,3B52E passes it to57E88, and3B54E passes the same pointer/4096-byte slice to24754 for endpoint82. Next command/block reuses that address. A normal READ10 is not a512-byte transfer: the512-byte record in this phase is the BPB-bearing prefix of the4096-byte USB response. No truncated512-byte USB result is accepted. b13-0803b27c.asm (local-only reference: `builds/phase50-msd-readonly-geometry/b13-0803b27c.asm`; not distributed); b13-08057e30.asm (local-only reference: `builds/phase50-msd-readonly-geometry/b13-08057e30.asm`; not distributed).

**PROVEN:**57EA2→1A7E4 zeroes all requested4096 bytes before queue wait and raw read. Physical DMA then overwrites some/all of that buffer. After normal return the optional serial-marker filter may change response RAM; our BPB/FAT/root fixtures have no such marker. The buffer remains the returned data after the data stage and CSW, until another clear/write. CSW uses its separate protocol structure. b13-0801a7e4.asm (local-only reference: `builds/phase51-msd-read-safety/b13-0801a7e4.asm`; not distributed); [read10-physical-path.md](<../phase51-msd-read-safety/read10-physical-path.md>).

**PROVEN pointer flow:**24754→389C6 stores the supplied buffer pointer at the selected IN endpoint record+0C, length at+14, then calls4862A. No sector-sized copy occurs in SCSI or these wrappers; the USB driver retains a pointer into the shared buffer. **UNKNOWN:** complete USB FIFO/IRQ ownership/quiescence across real command completion; the native runner snapshots bytes at the TX boundary and models completion before admitting the next command. b13-08024754.asm (local-only reference: `builds/phase52-read-authentication/b13-08024754.asm`; not distributed); b13-080389c6.asm (local-only reference: `builds/phase52-read-authentication/b13-080389c6.asm`; not distributed).

**PROVEN modeled lifetime:** all sequential commands use the same emulator RAM allocation. Each physical-read seam asserts4096 zero bytes before supplying data, irrespective of the previous target/control. Thus a partial target gives `new target prefix + zero suffix`, not `new target prefix + old control suffix` in this model. An actual late DMA/USB race is not disproved by that assertion. Native response clearing, queue wrapper/worker, backend semaphore/release, SCSI and CSW execute; DMA bytes, task wake/queue movement and USB transfer completion are explicit seams.
