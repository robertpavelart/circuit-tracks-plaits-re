# Phase65: exact SHI transition and minimum model

**PROVEN:** `0x200100` is a 24-bit command word, not an ARM address or a register location. ARM `080295E4` emits bytes `20 01 00` at `08029600→0803BAA2→08037960`, on the DSP command lane. The SPI2 peripheral still shifts 8-bit bytes. The receiving DSP's SHI changes its word framing from three bytes to two bytes.

**PROVEN by the original DSP code:** the SHI receive handler reads HRX at `X:$FFFF94`, tests command/data GPIO `X:$FFFFBD` bit8, and stores this command in `X:$12` at P:$0163. The native main loop at P:$0113 clears pending bit21, conditionally calls P:$012D, tests width bit8, and writes HCSR `X:$FFFF91` through `$10A4→$10A5`; HCKR `X:$FFFF90` receives3. P:$013E clears GPIO bit9. `X:$12` retains `$000100`; it is not required to become zero. The reverse command is the two-byte `20 00`, received as `$200000`; native P:$0130–$0134 restores HCSR `$10A9`. Sources: candidate-080295e4.asm (local-only reference: `builds/phase65-shi-model-closure/candidate-080295e4.asm`; not distributed), DSP-0113-013f.asm (local-only reference: `builds/phase65-shi-model-closure/DSP-0113-013f.asm`; not distributed), DSP-0156-01b3.asm (local-only reference: `builds/phase65-shi-model-closure/DSP-0156-01b3.asm`; not distributed), and the existing [DSP command map](<../../../notes/dsp-command-map.md>).

**PROVEN:** command/data and chip-select operations remain native ARM helpers `08029190/080291A2/080291B8/080291CA`. The model observes them and clocks the actual SPI DR bytes; it does not substitute their return values. DSP HRX/data-store semantics are modeled as complete received words: in 16-bit mode the first byte occupies bits23..16, the second bits15..8, and bits7..0 are zero. The saved pointer advances only after the second byte. P:$0198–$019E selects X/Y from saved command flags and performs the receiving store.

**PROVEN within this abstraction:** [dsp_peer.py](<../../../builds/phase65-shi-model-closure/dsp_peer.py>), `BootPeer.byte/commit/dma`, keeps word framing and delayed SPI receive completion separate. The inherited [spi2_model.py](<../../../builds/phase65-shi-model-closure/spi2_model.py>) supplies bounded TX/RX FIFO progress; TXE does not imply RXNE. Width control is consumed by the original DSP main loop before the parser changes framing. There is no unconditional idle mailbox response for the new table jobs.

[native_dsp.py](<../../../builds/phase65-shi-model-closure/native_dsp.py>), `NativeDSP`, keeps the existing strict-flow emulator alive through all table requests. It loads the unchanged candidate DSP programs, uses original bootstrap entry PCs100/107, pauses at25F3, admits only X/Y values already delivered by this live ARM run, then resumes naturally at113. Subsequent mailbox polling executes `TURN 113`; it does not assign PC, use a P:$7000 trampoline, or patch P:$0281. Native `P:$1C53/$1D41/$1DA8` creates, advances and clears the deferred table work.

**STRONG INFERENCE:** one native main-loop turn per observed mailbox read is a suitable asynchronous progress abstraction for this startup workload. It is not calibrated DSP/ARM timing, a cycle-accurate SHI FIFO/interrupt model, or a proof of all DSP state between ARM polls. Early boot-ready exchange and bootstrap DMA reuse the scoped Phase64 model. Native DSP initialization is staged from wire-derived state; no prepared ARM RAM or geometry state is inserted mid-run.

**UNKNOWN outside this scope:** arbitrary SHI commands, hardware overrun/recovery, cycle deadlines and autonomous DSP progress after ARM stops polling are not qualified. DSP shared/external backing is the existing emulator allocation, not a new grant of physical memory ownership to the diagnostic or Plaits. No firmware image was generated or changed.
