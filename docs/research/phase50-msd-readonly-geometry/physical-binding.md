# Phase50 — physical binding, not FAT resemblance

**PROVEN code equation:** USB LUN0→SCSI3B52E→initialized callback57E88→`[20006968]` raw NOR wrapper24130→op1/worker2408A→backend22F94. The callback reads base from `[200037C0]`; internal mode1 selects record8038C3C/base94000. It passes `address=base+(USB_LBA<<12)`, not a disk-file offset. b13-08057e30.asm (local-only reference: `builds/phase50-msd-readonly-geometry/b13-08057e30.asm`; not distributed); b13-08024130.asm (local-only reference: `builds/phase50-msd-readonly-geometry/b13-08024130.asm`; not distributed); b13-08023f68.asm (local-only reference: `builds/phase50-msd-readonly-geometry/b13-08023f68.asm`; not distributed); [filesystem-lba-binding.md](<../phase46-msd-filesystem-closure/filesystem-lba-binding.md>).

**PROVEN independent application binding:**20000A98 holds internal disk0 baseD4000,stride1000;20000AA0 is disk0,FS20000AB0. Application filesystem mapper1AF1E uses `D4000+1000*disk_LBA`. Thus, in stable mode1, `USB_LBA=40hex+disk_LBA` gives exactly the same physical NOR address. This is established by native address arguments and unchanged initialized objects, not sector contents. [live-geometry-structure.md](<../phase49-existing-geometry-reader/live-geometry-structure.md>); native-reads.json (local-only reference: `builds/phase50-msd-readonly-geometry/native-reads.json`; not distributed).

**PROVEN narrow native checks:** mode1 LBA0→94000; mode1 LBA40→D4000; internal2 LBA0→D4000; internal3 LBAD4→D4000. Synthetic response bytes were injected at the wrapper seam. These results prove address calculation/selection; they do not prove an acquired sector's source or current mode. Capacity and inquiry are identical across windows and cannot establish the selected base. A FAT-looking sector alone is insufficient.

For a mounted volume starting at disk LBA V, first VBR is USB LBA40+V, FAT is40+V+reserved, data is40+V+reserved+nFAT*fatsz+rootS. Valid file mappings are `NOR=D4000+1000*(database+(cluster-2)*spc+sectorWithinCluster)`; both FAT copies and root/FSInfo domains must also be bounded. The decoder uses wide arithmetic and rejects a volume outside disk0's normal7980 sectors to prevent treating wrapped mappings as normal.

**PROVEN normal target relation:**81000−D4000 =−53000, or disk LBA−53hex;82000−D4000 =−52000, disk LBA−52hex. These are below any normal bounded internal volume mapping. In mode1 they would be negative USB LBAs−13hex/−12hex. No such read is requested. A validated BPB closes the geometry equations for those normal write domains; it does not independently close unrelated raw writers, dirty RAM lifetime, or current-unit acquisition provenance. [target-address-equations.md](<../phase47-filesystem-state-closure/target-address-equations.md>); geometry-tests.json (local-only reference: `builds/phase50-msd-readonly-geometry/geometry-tests.json`; not distributed).
